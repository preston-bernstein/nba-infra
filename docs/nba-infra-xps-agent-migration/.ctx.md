## CLAUDE.md
Infrastructure glue for the NBA stack (nba-analytics-hub Node API, nba-data-service Go feed,
nba-predictor Python inference), not an application repo — owns Compose files, reverse proxy
config, env var contracts, operational scripts only. Deployment philosophy: deployment mode
changes configuration, not architecture; no Kubernetes for MVP; Node API is the only public
backend; Go/Python stay private on the Docker network. Strict rules for this repo specifically:
no AI-assistant attribution anywhere (commits, docs, comments — attribute all work to Preston
Bernstein only), ask before architectural changes, "Deploy this" requests must ask WHERE.
Source-of-truth hierarchy: DECISIONS.md (nba-analytics-hub) > DEPLOYMENT_PLAN.md (docs-internal)
> DEPLOYMENT.md > AWS_REFERENCE_ARCHITECTURE.md (reference only) > this file.

## Additional live-state facts (not derivable from repo docs alone)
- Two separate deployments exist: production on a DigitalOcean droplet (`nba-api.prestonbernstein.com`,
  `docker-compose.prod.yml`, untouched by this migration) and a desktop-only instance on
  desktop-agent (`docker-compose.desktop.yml`, undocumented anywhere in this repo's own docs —
  this migration's actual subject).
- Desktop-agent's instance: dedicated `nba-app` service user, home dir `/opt/docker/nba-app/`,
  containing four sibling repo checkouts (`nba-infra`, `nba-analytics-hub`, `nba-data-service`,
  `nba-predictor`) side by side. All four repos are public on GitHub — no auth needed to clone.
- Three services (`api` :3020->3000, `go-feed` internal/uid0, `predictor` internal), three named
  Docker volumes (`nba-infra_go-data`, `nba-infra_predictor-data-cache`, `nba-infra_predictor-artifacts`,
  combined under 20KB), one `.env` at `/opt/docker/nba-app/.env` (~10 vars incl. `BALLDONTLIE_API_KEY`).
- No systemd unit, cron job, or wrapper script manages it — brought up once manually, kept alive
  by each service's `restart: unless-stopped` policy.
