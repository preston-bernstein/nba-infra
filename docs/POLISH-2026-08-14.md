## Findings and fixes applied

1. **`.env.example` drift** (real — this file is this repo's declared "environment
   variable contract," per `CLAUDE.md` §7 and `DEPLOYMENT.md`'s own "keep it in sync"
   note):

     referenced anywhere in this repo (grepped compose files, scripts, README,

     service; these were orphaned template entries.

     `${VAR:-default}` in `docker-compose.prod.yml` and `docker-compose.desktop.yml`,
     and already documented as overridable in both `README.md` and `DEPLOYMENT.md`,
     but missing from the one file meant to declare the contract.
   - Kept the `DOMAIN` addition that was already staged uncommitted before this pass
     started (it's correct: `docker-compose.prod.yml` requires it, `Caddyfile` reads
     it) — folded it into the same commit rather than leaving it dangling.

2. **`README.md` stale line**: "`Caddyfile` (local-only; update with domain + HTTPS
   later)" was left over from before `ccd8785`. The Caddyfile has handled `DOMAIN`-based
   prod HTTPS *and* local `:80` since that commit — `ROADMAP.md` and `DEPLOYMENT.md`
   already said so correctly; only this one README line hadn't caught up. Fixed to
   match.

3. **`docs-internal/DEPLOYMENT.md` and `docs-internal/ARCHITECTURE.md`** (gitignored,
   local-only — not part of the git history, so not part of the commit below, but real
   content on disk and explicitly called out in this repo's own `CLAUDE.md` §12 as
   something to keep in sync): the internal deployment doc still described
   `docker-compose.prod.yml` as building from sibling repos and owning the uvicorn
   serve command — both now live in the shared base `docker-compose.yml` post-`ccd8785`.
   Updated the prod section and the `Commands` block to match the (already-accurate)
   public `DEPLOYMENT.md`. `ARCHITECTURE.md`'s one-line description of
   `docker-compose.prod.yml` updated similarly.
